# Moleculab documentation

Moleculab has three documentation responsibilities. Start with the entry point
that matches your goal.

| Goal | Entry point |
| --- | --- |
| Understand the project and install it | [Project README](../README.md) |
| Learn computational drug discovery | [Tutorials](tutorials/README.md) |
| Develop Moleculab | [Development guide](development/README.md) |
| Look up a definition or validation check | [Reference](reference/README.md) |
| Browse runnable examples | [Examples](../examples/README.md) |

## What lives where

| Area | Contents |
| --- | --- |
| [`tutorials/`](tutorials/README.md) | Track A physics, Track B chemistry, Track C drug discovery, and the imatinib capstone |
| [`reference/`](reference/README.md) | units, validation, troubleshooting, answer keys, visualization prompts, and the first-milestone derivation |
| [`development/`](development/README.md) | architecture, roadmap, performance, acceleration, testing, and contribution guidance |
| [`internal/`](internal/README.md) | non-user-facing background material retained for development history |

The tutorial path is intentionally:

```text
README.md → tutorials/ → track landing page → module → capstone
```

The root README is the project overview, not a second curriculum. The
development guide is for contributors, not for first-time learners.
